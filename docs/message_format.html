Layout of this message

Sections follow each other with no padding, always in this order. The header holds every length, so a reader finds any section without scanning.

Storage classes

A field's type decides its class. The class is part of the wire encoding and never changes for a field ID.

ClassTypesWhere the value is

What the format guarantees

Zero-copy reads

A getter returns a scalar or a string_view into the stored bytes. Nothing is parsed or allocated.

O(1) access

Any field, present or absent, is a bit test, a popcount and a load. Opening a message reads only the header.

Self-describing

Bitmap positions are field IDs, so a reader locates every field without the writer's schema.

Backward compatible

New code reads old messages: a field the message lacks is a clear bit and reads as its default.

Forward compatible

Old code reads new messages: addressing depends only on the bitmaps, so extra fields do not disturb known ones.

Unknown fields survive

Patches and rebuilds work on storage classes, not schemas. Fields a reader does not know are preserved byte for byte.

Partial updates

Any present scalar or equal-length string is overwritten in place. Other changes splice the payload or rebuild.

Explicit presence

A field set to 0, false or "" differs from an absent one: presence is its own bit.

Canonical

Equal field sets encode to equal bytes. Section order, ID order and all widths follow from the content.

Safe on any input

Reads of malformed bytes stay inside the buffer. MessageView::Verify detects them before use.

Evolving a schema

Only backward-compatible evolution is supported, by design.

table Account {
  id: ulong;                   // A field keeps its ID and type forever.
  nickname: string (deprecated); // Unused fields are deprecated: no accessors, ID stays reserved.
  email: string;               // New fields are appended.
}

Field IDs run from 1 to 2040. Bitmaps grow with the highest ID present in each class, so dense IDs are cheapest: try the High field ID example. The full specification is in message_format.md.
